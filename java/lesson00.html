Before You Code

Understand the problem. Plan your steps. Build and test a little at a time.

How to start when you don’t know what to type

You read a coding question. Then you open an empty file.

“What do I type first? Do I need int or double? Where do the brackets go?”

That can feel overwhelming because you are trying to solve the problem and remember Java’s rules at the same time.

Give yourself a smaller first task: explain what the program needs to do. You can use ordinary English, a few numbers, or a sketch.

You do not need perfect Java syntax to begin thinking.

1. Find the input and the output

Before writing code, complete these two sentences:

  • The program receives…
  • The program must display…

For example:

Ask the user for two integers and display the larger number. If they are equal, say so.

Your answers:

  • The program receives two whole numbers.
  • The program displays the larger number, or a message saying they are equal.

You now know where the program starts and what it must achieve.

2. Solve a small example yourself

Pretend you are the computer.

If the numbers are 8 and 3, what should you display?
8 is larger than 3.

Now ask: How did I decide that?

“I compared the two numbers. Eight is greater than three.”

Try a different case:

First numberSecond numberExpected result
838 is larger than 3
388 is larger than 3
55The numbers are equal
-4-1-1 is larger than -4

These examples help you discover the cases your program needs to handle.

If you cannot solve an example yet, stay with the problem for a moment. Clarify the rule or ask for an explanation before trying to write Java.

3. Write a plan in ordinary words

Describe the steps clearly enough that someone else could follow them.

For the larger-number problem:

  1. Read the first number.
  2. Read the second number.
  3. If the first is greater, display the first as the larger number.
  4. Otherwise, if the second is greater, display the second as the larger number.
  5. Otherwise, say that the numbers are equal.

This is an algorithm: a set of steps for solving a problem.

You can put your plan directly into your file as comments:

// Read the first number.

// Read the second number.

// If the first number is greater,
// display it as the larger number.

// Otherwise, if the second number is greater,
// display it as the larger number.

// Otherwise, display "The numbers are equal".

Java ignores comments beginning with //. They are notes for you. They will not perform the steps until you add code.

4. Choose the Java tools your plan needs

Now you have a reason to choose each tool.

You do not have to memorize every Java feature before solving a problem. Look up the particular tool your next step needs.

“I need to read a whole number and save it.”

After setting up a Scanner named input, that becomes:

int num1 = input.nextInt();

The idea came first. The Java statement expresses that idea.

5. Build one small working part

Do not wait until the entire program is written before running it.

Start with a working class and main method. It is okay to use your class notes or a familiar starter template for this structure.

Then build gradually:

Small goalHow to check it
Read the first numberPrint it back temporarily
Read the second numberPrint both numbers
Handle the first number being largerTry 8 3
Handle the second number being largerTry 3 8
Handle equal numbersTry 5 5

Printing a value temporarily helps you check what your program actually stored. Remove extra checking messages when the program works and the assignment needs a particular output.

Each successful run gives you a working starting point for the next change.

6. Compare the result with your prediction

Before pressing Run, ask:

“For this input, what exactly should appear?”

Then compare your prediction with the actual output.

Test different kinds of cases:

  • A normal example.
  • A different branch.
  • Equal values, when relevant.
  • Zero or negative numbers, when allowed.
  • Values exactly at a cutoff.

For the marks exercise, test 80 and 79.9. They are close together, but they should produce different levels.

One successful example is a useful start. It does not show that every case works.

When something goes wrong

First identify what kind of help you need.

What happens?Your next move
You cannot explain how to get the answerWork through a smaller example in ordinary words
Java reports a compilation errorRead the first error; check that line and the line just before it
The program starts but crashesRead the error and inspect the input or operation that caused it
The program runs but gives the wrong resultTrace the values and conditions one step at a time

For a wrong result, ask:

  1. What values are stored?
  2. Is this condition true or false?
  3. Which branch will run?
  4. What will it print?

Change one thing you understand, then run again. Avoid changing several unrelated lines just to see whether the error disappears.

How to ask for a useful hint

Tell your teacher, a classmate, or an AI helper what you have already figured out and where you are stuck.

“I know I need two integers and three possible cases. Can you check my steps before I write the code?”

“I want to read a decimal number. Which Scanner method should I look at?”

“I expected Level 3, but got Level 4. Help me trace my conditions without rewriting my program.”

A useful hint should help you take the next step yourself.
