1. A decision inside another decision

A nested if is an if inside another if. Java reaches the inner condition only when it enters the outer block.

int mark = 75;
if (mark >= 70) {
    if (mark < 80) {
        System.out.println("Level 3");
    }
}
markOuter: mark ≥ 70Inner: mark < 80Output
65falseNot checkedNothing
75truetrueLevel 3
80truefalseNothing
81truefalseNothing

For this example, the inner print needs both conditions to be true. It can also be written as if (mark >= 70 && mark < 80). Nesting is useful when each stage needs its own actions or messages.

2. Which else belongs to which if?

The classroom driving example is a simplified programming rule: age at least 16, then check a boolean license value.

int age = 16;
boolean hasLicense = false;
if (age >= 16) {
    System.out.println("You are old enough to drive!");
    if (hasLicense) {
        System.out.println("You can drive!");
    } else {
        System.out.println("Do a driver's test!");
    }
} else {
    System.out.println("You must be 16 & licensed to drive!");
}
ValuesPathOutput
16, falseOuter true → inner falseOld enough message, then driver’s test message
17, trueOuter true → inner trueOld enough message, then can drive message
15, trueOuter false → outer elseMust be 16 & licensed message only

The inner else handles “old enough, but no license.” The outer else handles “not old enough.” Indentation helps people read it; braces determine the blocks. An else attaches to the nearest unmatched if allowed by those blocks.

if (hasLicense) means the same thing as if (hasLicense == true). The shorter version is enough.

3. Check first; read second

hasNextInt() checks whether the next token can be read as an int. It returns true or false and does not consume the token. nextInt() reads and consumes it. The check can wait for input if none is available yet.

PurposeCheckRead
Whole numberhasNextInt()nextInt()
Decimal-capable numberhasNextDouble()nextDouble()
true or falsehasNextBoolean()nextBoolean()
A word/tokenhasNext()next()

There is no hasNextChar(). Scanner normally separates tokens using whitespace (spaces, tabs or line breaks). An integer token such as 4 can also be read as a double.

if (input.hasNextInt()) {
    int number = input.nextInt();
    if (number >= 0 && number <= 10) {
        System.out.println("Valid: " + number);
    } else {
        System.out.println("Integer, but outside 0-10");
    }
} else {
    System.out.println("Not an integer");
}

Two separate questions: Is the type correct? Then is the value in range? This if version makes one attempt. Lesson 1.7 adds repetition so the user can try again.

4. Trace the classroom example

Same structure as the teacher’s class code; the Scanner is named input here instead of console. Use either name consistently.

Show complete classroom-style code
import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        Scanner input = new Scanner(System.in);

        System.out.println("Enter an integer and a decimal number separated by a space:");
        if (input.hasNextInt()) {
            int firstNumber = input.nextInt();
            if (input.hasNextDouble()) {
                double secondNumber = input.nextDouble();
                System.out.println("First number " + firstNumber);
                System.out.println("Second number " + secondNumber);
            } else {
                System.out.println("This is invalid. You must enter a double.");
            }
        } else {
            System.out.println("This is invalid. You must enter an integer as the first value.");
        }

        input.close();
    }
}

5. Try without looking at the answers

These are extra review tasks based on the lesson, not a separate teacher exercise sheet.

Task 1: trace it — then show answer

For the marks example, predict the output for 69, 70, 79 and 80.

Answer

69: nothing. 70: Level 3. 79: Level 3. 80: nothing.

Task 2: Write comment steps for accepting an integer between 0 and 10. Explain why the range check must happen after the type check.

Answer

Check whether an integer is available → read it → check 0 ≤ number ≤ 10 → print a valid or range-error message. If the type check fails, print a type-error message. Calling nextInt on text before checking can cause an InputMismatchException.

Task 3: Will two calls to hasNextInt read two different values?

Answer

No. Neither consumes input. Without a read between them, both check the same next token.

Common mistakes

  • Checking the inner condition even though the outer condition is false.
  • Assuming every else means “all earlier conditions failed.” Match it to its own if.
  • Using nextInt before checking whether the token is an integer.
  • Assuming hasNextInt removes invalid input. It does not.
  • Using a variable after a branch even though it might never have been assigned a value.
  • Writing 0 <= number <= 10. Java needs number >= 0 && number <= 10.
