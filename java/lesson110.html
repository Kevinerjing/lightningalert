Exception Handling

Understand what failed, handle it, and decide whether to ask again.

Plan the recovery

Before syntax: Which operation might fail? What message would help? What input must be discarded? Should the program retry or stop?

try runs potentially failing code. If a matching exception occurs, Java jumps to catch. Successful handling lets execution continue; it does not undo earlier work or automatically retry the failed statement.

Follow try and catch

try {
    number = input.nextInt();
    // reached only if the read succeeds
} catch (InputMismatchException e) {
    System.out.println("Please enter an integer.");
    input.next();
}

e is a variable holding the exception object. You may rename it. The type name must be written correctly: InputMismatchException, without spaces.

System.err.println, used in class, writes to the error stream; it is not what catches the error. System.out.println is enough for these friendly messages.

Complete retry example

Show complete beginner solution
import java.util.Scanner;
import java.util.InputMismatchException;

public class Main {
    public static void main(String[] args) {
        Scanner input = new Scanner(System.in);

        boolean askAgain = true;
        int number = 0;
        do {
            try {
                System.out.println("Enter an integer:");
                number = input.nextInt();
                askAgain = false;
            } catch (InputMismatchException e) {
                System.out.println("Not an integer. Please try again.");
                input.next(); // consume the bad token before retrying
            }
        } while (askAgain);
        System.out.println("You entered " + number);

        input.close();
    }
}

next() discards one token. nextLine() discards the remainder of the current line, as in one class example. Either can be intentional; know which input you want to discard. These console examples assume the user continues providing input.

Type checks and range checks

hasNextInt() checks whether the next token can be read as an int without consuming it. hasNext() only checks for a token; it does not validate an integer.

After a successful read, use if for rules such as positive, five digits or at most 100. try/catch does not recognize an unwanted range as an exception.

Show complete beginner solution
import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        Scanner input = new Scanner(System.in);

        int number = 0;
        while (number < 10000 || number > 99999) {
            System.out.println("Enter a five-digit integer:");
            if (input.hasNextInt()) {
                number = input.nextInt();
                if (number < 10000 || number > 99999) {
                    System.out.println("Use a number from 10000 to 99999.");
                }
            } else {
                System.out.println("Please enter an integer.");
                input.next();
            }
        }
        System.out.println("Valid number: " + number);

        input.close();
    }
}

Classroom lottery input validation: hello, 9999 and 100000 are rejected; 10000 and 99999 are accepted. Leading zeros are not preserved in an int, so 01234 is treated as 1234 and rejected. This matches the teacher’s numeric range rule; it is not a complete lottery game.

Six paper checks

1. What catches what?

nextInt reads hello. Which exception from this lesson is thrown?

Check answer and reasoning

InputMismatchException. The token does not represent an int.

2. Follow the jump

try {
    int n = input.nextInt();
    System.out.println("A");
} catch (InputMismatchException e) {
    System.out.println("B");
    input.next();
}
System.out.println("C");
Check answer and reasoning

For hello: B then C. For 7: A then C. The remaining statements in try are skipped when nextInt throws.

3. Does catch retry?

If this try/catch is used without an enclosing loop, does it ask again automatically?

Check answer and reasoning

No. The loop causes a retry; catch only handles the matching exception.

4. Find the repeated failure

Why does deleting input.next() from the retry example cause trouble?

Check answer and reasoning

The invalid token stays unread. The next iteration tries to read the same token and fails again.

5. Type or range?

For an age restricted to 0–120, does entering -5 trigger InputMismatchException?

Check answer and reasoning

No. -5 is a valid int. Use if to reject the range after reading the integer.

6. A different exception

Will catch (InputMismatchException e) handle integer division by zero?

Check answer and reasoning

No. That throws ArithmeticException. A catch must match the thrown exception type (or an appropriate superclass).

Common mistakes

  • Keep imports above the class; do not put them inside main.
  • Set the retry flag to false only after a successful read.
  • Consume invalid input before trying again.
  • Declare a value before try if you need it after try/catch; initialize it where Java requires definite assignment.
  • Catching an exception does not fix syntax or logic errors.

The handout says try is always followed by catch. That describes this lesson’s pattern; Java also has try/finally and try-with-resources forms, which are outside this lesson. A handled exception need not crash the program first.
